# bad-apple-parody

Bad Apple!! の各フレームを「実在するものの形」から探して再現する実験。
きっかけは、地球の衛星写真の雲から各フレームに合う形を探して並べた動画。

現在の本命は **日本の市区町村の形で Bad Apple!! を再現する** 案。

## これまでの検討

### 方向性
- 「01 で表現できる媒体に描く」系はやり尽くされているので対象外。
- 雲の動画の面白さは「実在する大量のデータの中に、その形が本当に見つかる」点。手法自体はフレームごとに一致する形を探して並べるだけ（パラパラ漫画で構わない）。
- ソフトウェアだけで完結し、誰でも知っている題材が望ましい。

### 検討した案と判断
| 案 | 判断 |
|---|---|
| 市区町村の形（隣接結合も候補） | **採用。試作で手応えあり（後述）** |
| 世界の国・島（Natural Earth） | 候補。市区町村版の世界地図版。数が少ない |
| 漢字1文字（Noto CJK 約6万字） | 候補。手軽 |
| 絵文字（Noto Emoji） | 候補 |
| テトリスの合法手順で盤面を作る | 候補 |
| 国土地理院航空写真 / OSM 建物ポリゴン | 候補。Google マップは規約上大量取得不可 |
| マンデルブロ集合の中から探す | 試作したが不可。自己相似性のため「塊＋放射状の枝」しか出ない |
| Minecraft のシード探索 | 却下。Minecraft の Bad Apple は既出 |
| 逆算ライフゲーム、流体制御、群れ、カム機構など | 却下（方向性が違った） |

## 実験1: マンデルブロ集合（`mandelbrot/search.py`）

テスト用シルエット（64×48）に対し、ランダム 6000 窓＋山登りで探索。しきい値は発散速度に対して窓ごとに最適化。
白黒それぞれの IoU の平均でりんご 0.79、人型 0.74 だが、見た目は「塊から突起が出た形」で判別不能。→ 不採用。
結果: `results/mandelbrot/`

ジュリア集合や Burning Ship 等へ広げれば余地はあるが未検証。

## 実験2: 市区町村の形（`municipality/`）

### データ
- 市区町村境界: 国土数値情報（行政区域 N03、2021年）を [smartnews-smri/japan-topography](https://github.com/smartnews-smri/japan-topography) が簡素化したもの（簡素化1%版）。1902 市区町村（政令市は区単位）。出典表記が必要。
- Bad Apple!! フレーム: [irqd/bad-apple](https://github.com/irqd/bad-apple) の `src/public/images/frames/frame-0001.jpg`〜`6572`（960×720）。著作物なのでコミットしない。

### 手法（`match.py`）
1. 各市区町村を局所等距円筒図法で平面化（面積が最大パーツの5%未満の離島は除外）。
2. 目標フレームを W×H に縮小・二値化（白が照合対象）。
3. 各市区町村を 7.5° 刻み回転 × 左右反転で、目標の白領域のバウンディングボックスに面積比で合わせて配置し、ラスタライズして IoU（白領域）を計算。
4. 隣接する市区町村を最大6つまで結合するビームサーチ（幅40）。
5. 最良候補を回転・拡縮・平行移動の山登りで微調整し、画像を出力。

### 結果
| 目標 | 一致 | IoU（白領域） |
|---|---|---|
| Bad Apple!! frame 4500（ドレスの人物、96×72） | 三重県鈴鹿市 | 0.80 |
| Bad Apple!! frame 0900（立ち姿、反転、96×72） | 千葉県我孫子市 | 0.82 |
| テスト: りんご | 東京都千代田区 | 0.83 |
| テスト: 上半身 | 埼玉県吉川市（結合で下條村＋売木村＋泰阜村＋阿南町 0.856） | 0.85 |
| テスト: 人型（手足あり） | 千葉県館山市 | 0.62 |

鈴鹿市は頭・胴・スカートの輪郭まで合い、見て分かるレベル。腕・髪飾りなど細い部分は出ない。
1フレームあたり約20秒（単一コア）。結果: `results/municipality/`（左が目標、右が一致した形）

### 分かった課題
- **隣接結合がほぼ効かない**: ビームの初期値を「単体で良い市区町村」にしているため、単体最良を超えにくい。初期値の選び方を変える必要がある。
- **複数の人物・画面全体の絵に未対応**: 5700 や 6300（陰陽玉）のようなフレーム。連結成分ごとに別の市区町村を当てる、背景側（黒）を当てる等が必要。
- **動画化するとちらつく**: フレームごとに市区町村が変わる。一定区間は同じ市区町村を保持し、回転・拡縮で追従させる設計が要る。
- **速度**: 全 6572 フレームで約36時間。並列化、形状特徴量（Huモーメント、輪郭フーリエ記述子など）による事前絞り込みが必要。
- 境界は簡素化1%版なので輪郭が粗い。高精度版は国土数値情報の原データ。

## 実験3: 全フレーム処理・ちらつき対策・複数物体（2026-11-26）

### 高速化（`common.py`, `score_all.py`）
- 各市区町村を「重心を中心・面積を一定」にそろえ、48 角度 × 左右反転で 64×64 のビットマスクにしておく（バンク、約15秒）。
- フレームの図形も同じく重心・面積でそろえ、ビット演算（AND と popcount）で全候補との IoU を一度に計算する。
- 全 6572 フレームで約2分（従来方式の見積もりは約36時間）。
- 図形側は「画面の縁で多い色を背景」として自動判定（2797 フレームが黒い図形）。
- 細長い市区町村は、姿勢によっては 64×64 からはみ出す。はみ出すと切れた形のまま高得点になるので、その姿勢は照合から外す（全体の4%）。

画面全体を1つの図形として照合すると、各フレームの最良 IoU は平均 0.67（中央値 0.72）。10番目の候補でも平均 0.64 で、1位との差は小さい。

### ちらつき対策（`sequence.py`）
状態を（市区町村, 反転）とし、切り替えるたびにペナルティ λ を引く Viterbi で割り当てる。区間が決まったあと、角度は 7.5° 動くたびに 0.01 を引く経路で追従させる（角度追従による IoU の低下は 0.002 程度）。

| λ | 区間数 | 平均保持 | IoU |
|---|---|---|---|
| 0（毎フレーム最良） | 3015 | 0.07 秒 | 0.672 |
| 0.3 | 343 | 0.64 秒 | 0.655 |
| 1 | 143 | 1.53 秒 | 0.638 |
| 2 | 84 | 2.61 秒 | 0.625 |
| 4 | 44 | 4.98 秒 | 0.607 |
| 8 | 16 | 13.7 秒 | 0.580 |

### 連結成分ごとの割り当て（`tracks.py`）
- 図形を連結成分に分け（画面の 0.2% 未満は無視）、前フレームの成分と重なりで対応づけてトラックにする。9195 成分、544 トラック。
- 成分のあるフレームのうち、2つ以上の成分があるのは 1930 フレーム（30%）。
- 画面外は「どちらでもない」として IoU から除外する。画面端で切れた図形の直線に、四角い市区町村が引きずられなくなった。
- トラックごとに上の Viterbi を回す。λ=1 で成分ごとの IoU 平均 **0.74**（画面全体を1つで当てる方式は 0.64）。
- 2人の場面（frame 2857・4135）や複数の物体の場面（3816）が、それぞれ別の市区町村になった。

### 見た目の評価（全編プレビュー `render.py` / `tracks.py render`）
- 人物1人の立ち姿・ティーカップ・りんごなど輪郭が単純な場面は、形として通用する。
- 腕・ほうき・バイオリンの弓・髪飾りなど細い部分は出ない（市区町村の形の限界）。
- 画面いっぱいの図形（frame 940・1579 など）は形の印象が弱い。
- 縁の色で図形側を決める判定は、月と人物の場面（3177）のように外れることがある。

### 分かった課題
- **トラックが細切れ**：腕が体に付いたり離れたりするたびに成分が分裂・合体してトラックが切れる（中央値 0.1 秒）。成分方式だと、最大成分の市区町村は平均 0.66 秒に1回変わる。分裂・合体の前後でトラックをつなぐ工夫が要る。
- 角度は 7.5° 刻み、位置・大きさは重心と面積で決めているだけ。最終出力では区間ごとに微調整（従来の `refine`）をかけたい。
- 境界は簡素化1%版なので輪郭が粗い。

## 実験4: ちらつき対策の改良（`objects.py`）

### やったこと
- **近い塊をまとめて1物体に**：図形を 4px（240 幅基準）膨張させた連結成分を1物体とし、照合もまとめた形で行う。9195 成分 / 544 トラック → 8645 物体 / 461 トラック。
- **分裂・合体時の引き継ぎ**：新しいトラックが前フレームのどの物体と重なっていたかを親として記録し、親と同じ市区町村を選ぶと得になるボーナス（λ と同じ値）を付ける（親ありのトラックは 139 本）。
- **場面転換（カット）の検出**：白黒反転、または「画面の 8% 以上が変化し、図形の重なりが 3 割未満」をカットとする（109 フレーム）。カットでは切り替えの減点を 0.05、それ以外では λ にする。
- **最低保持時間**：カット以外では 0.5 秒（15 フレーム）未満で切り替えられない制約を Viterbi に入れる（状態に「切り替えてからの経過フレーム」を持たせる）。
- **描画**：位置・大きさを時間方向に平滑化（σ=1.5 フレーム）。カット以外の切り替えは、前後 8 フレームで両方の形の符号付き距離場を混ぜてモーフィングする。名前は 20 フレーム以上続く区間だけ、フェードで出す。

### 結果
見た目に効く切り替え（カット以外で、同じ物体の市区町村が変わる回数。トラック内の切り替え + 分裂・合体時に親と別の市区町村になった回数）で比べる。

| 版 | 切り替え（全曲） | 間隔 | IoU（面積加重） |
|---|---|---|---|
| 実験3（`tracks.py`, λ=1） | トラック内だけで 95 回 ＋ 新トラックごとに選び直し | — | 0.742 |
| 改良版 λ=1 | 121 回 | 1.8 秒に1回 | 0.737 |
| **改良版 λ=3（採用）** | **34 回** | **6.4 秒に1回** | **0.717** |
| 改良版 λ=6 | 14 回 | 15.6 秒に1回 | 0.705 |

λ=3 で一番大きい物体の市区町村が変わるのは 206 回。そのうち 100 回はカット上、62 回は「2人のうち大きい方が入れ替わった」だけで、見た目のちらつきではない。

## 実験5: 見せ方（`aerial.py`, `design_proto.py`, `video_c.py`）

市区町村だと分かりやすくするため、航空写真・位置・回転角を添える。3 案を静止画で比べて **案C** に決めた。
- 案A: シルエットの中をカラー航空写真で塗る / 案B: シルエットは白黒のまま、右のカードに写真 / **案C: 案A の写真をモノクロにし、図形の白黒に寄せる**
- 回転して収まる演出は入れない。

### 決めたこと
- **左右反転は使わない**（`objects.py plan 3.0 --no-mirror`）。反転すると写真が実在しない鏡像の土地になる。物体ごとの最良 IoU は 0.769 → 0.763、割り当て後の IoU は 0.717 → 0.715 でほぼ同じ。
- **画像は地理院タイルの「全国最新写真（シームレス）」だけ**。出典の表記だけで使える（申請不要）。標準地図・淡色地図は、事前に描画した動画への利用に測量法の申請が要る場合があるので使わず、地図は境界データで自前で描く。
- ズームは市区町村の大きさで自動選択（外接矩形が約 900px になるズーム）。ズーム 13 以下はランドサット衛星画像（30m）で出典が別になる。使う 219 市区町村で 2085 枚・136MB（`data/tiles/` にキャッシュ、0.3 秒間隔で取得）。全部をズーム 14 の航空写真にすると約 3 万枚になるので見送った。
- 画面には短い出典（「画像：国土地理院（地理院タイル）」）だけ出し、正式な出典は動画の最後（5 秒）と概要欄に書く。
- モノクロ写真の明るさは市区町村ごとに 1 回だけ決める（形の内側の 2〜98% 点で正規化）。フレームごとに決めると明滅する。白い図形は 150〜255、黒い図形は 0〜100 の範囲に寄せる。

### 画面構成（1280x720）
- 左 960x720: 主画面。物体ごとにモノクロ航空写真で塗った形。切り替え時のモーフィングは形を符号付き距離場で、写真を重み付き平均で混ぜる。
- 右 320 幅の帯: 上端に元の映像（見出しなし、帯の幅いっぱい）、その下に映っている市区町村（最大 3）ごとの区画（県名・市区町村名、カラー航空写真（北が上）、日本地図上の位置）を縦に分割して並べる。余白は 8px に詰めて各画面を大きく見せる。
  - その瞬間に主画面にある形だけを出す（前の表示は残さない）。4 フレーム以上続く形と、最大の形（短くても）を並べる。並び順は、新しく加わったものを主画面で左にある順に後ろへ足す。
  - カットでは主画面と同時に即座に切り替える。カット以外で組が変わるときは、文字が重ならないよう前の組を消してから次の組を出す（各 2 フレーム）。
  - 主画面の上位 3 つの形がすべて右の帯に出ているフレームは 98.3%（切り替え中を除く）。最初は「0.7 秒以上続く形だけ・何もなければ前の表示を保つ」にしていたが、カットが続く区間で主画面と右の帯がずれた。
  - 「実際の形（北が上）」「回転角」の文字は冗長なので出さない。
- 音声は `add_audio.py <音声ファイル> [ずらす秒数]` で載せる（出力 `out/video_c_audio.mp4`）。動作確認では音声を再生せず、長さだけ確かめる。

全編の描画は約 5 分。

### 同じ形の重複禁止・都道府県と地方（`prep_areas.py`, `objects.py plan`）
- 同じフレームの別々の物体に同じ形を当てない。トラックを始まった順に割り当て、先に割り当てた物体が使っている形はそのフレームで −100 点にする（重複は 393 フレーム → 0）。
- 市区町村を合体させて 47 都道府県と 7 地方（東北・関東・中部・近畿・中国・四国・九州。北海道は都道府県と同じ）を作り、候補に加える。都道府県・地方は最大の島の 20% 未満の島を除く（鹿児島県の奄美などで形が散らばるため）。
- 都道府県・地方は、0.5 秒以上続き平均一致度 0.6 以上の区間だけ残す。満たさない区間はその物体では使わずに割り当て直す（収束まで繰り返す）。残ったのは中国地方（frame 48〜、0.83）・島根県（767〜、0.63）・和歌山県（1174〜、0.65）の 3 区間。市区町村より明らかによく合う場面は少ない（得点を 0.05 下げるだけで 1 つも選ばれなくなる）。

### 音声（`add_audio.py`）
- 音源はユーザーが用意した元の PV（`resources/original.mp4`、30fps・6572 フレーム・219.15 秒。著作物なので .gitignore 済み）。
- 映像のコマを突き合わせると、フレーム画像 frame-N.jpg は元の PV の (N+1) 番目（0 始まり）と一致した（3 か所で確認）。こちらの動画は 2 コマ早いので、音声の頭を 2/30 秒削って合わせる。音声は再生せず、長さとコマの対応だけで確かめた。

### 残っている課題
- 雲が写っている写真がある（喜界町など）。
- 原作のクレジット（楽曲・映像）は最後の出典画面に入れていない。

## 使い方（高速版）

```bash
cd municipality
python score_all.py                # data/bank.npz（初回のみ）と全フレームのスコア
python sequence.py sweep           # λ ごとの保持と IoU（画面全体を1つで当てる方式）
python sequence.py plan 1.0        # → data/plan_1.0.json
python render.py data/plan_1.0.json 4400 4700   # → out/preview_*.mp4（音声なし）
python tracks.py extract           # 連結成分の追跡と照合 → data/components.npz
python tracks.py plan 1.0          # → data/tplan_1.0.json
python tracks.py render 1.0        # → out/tpreview_*.mp4（音声なし）
python objects.py extract          # 物体単位の追跡・カット検出・照合 → data/objects.npz
python objects.py plan 3.0         # → data/oplan_3.0.json
python objects.py render 3.0       # → out/opreview_*.mp4（音声なし、モーフィング入り）
python objects.py plan 3.0 --no-mirror   # → data/oplan_3.0_nomir.json（航空写真を貼る版は鏡像なし）
python design_proto.py 1259 4455   # 見せ方 3 案の静止画 → out/design_{A,B,C}_*.png
python video_c.py                  # 案C の全編（航空写真を自動取得）→ out/video_c_0001_6572.mp4（音声なし）
ffmpeg -i out/video_c_0001_6572.mp4 -an -c:v libx264 -crf 26 -preset slow -pix_fmt yuv420p out/video_c_h264.mp4
```
Windows では `PYTHONUTF8=1` を付けて実行する（ファイル名や地名の文字コード対策）。
